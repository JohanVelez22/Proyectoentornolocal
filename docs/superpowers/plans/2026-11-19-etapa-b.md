# WolfCore Dev — Etapa B: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Montar cualquier proyecto (nuevo, desde GitHub, desde una URL de Git o una carpeta) con una receta guiada. Sumar Node y Python por proyecto, procesos supervisados, un panel de rendimiento, registros, Herramientas, el servidor MCP, tema Sistema/Claro/Oscuro, español e inglés y una interfaz pulida. Al final, montar los 6 proyectos reales del usuario.

**Architecture:** Todo vive en `packages/core` detrás de `Nucleo`: recetas, git/GitHub, runtimes, métricas, registros, herramientas y MCP. El token de GitHub nunca entra al núcleo en claro desde la configuración; lo guarda main con `safeStorage` y se lo pasa al núcleo por llamada. `apps/desktop` suma rutas IPC a la lista blanca y las pantallas. El modelo `Sitio` se amplía a un "proyecto": sitio, receta, procesos y git. El nombre interno sigue siendo `Sitio`; la interfaz dice "Proyecto".

**Tech Stack:** el actual, más `yaml` (para leer y escribir `wolfcore.yml`), `vue-i18n` v11, `qrcode`, `diff`, `bcryptjs` y `@modelcontextprotocol/sdk`. Las herramientas solo usan librerías MIT o BSD.

**Spec:** `docs/superpowers/specs/2026-11-19-etapa-b-design.md`. Siguen vigentes las specs de la Etapa A y del MVP.

## Global Constraints

- **Plataforma:** Windows primero. Todo proceso hijo nuevo lleva `windowsHide: true`. Los procesos de larga duración pasan por el `Supervisor`, con el lanzador oculto.
- **Textos y rutas:**
  - Ningún texto visible queda fuera de i18n: `es` y `en` deben tener las mismas claves, y una prueba lo comprueba.
  - Rutas con espacios, tildes y `’` en todo lo que se arme para PowerShell o cmd. Se usa `literalPowerShell` y se pasan los argumentos como arreglo (sin shell).
- **Secretos:**
  - El token de GitHub nunca se escribe en `config.json`, ni en `wolfcore.yml`, ni en remotos de git, logs o eventos, ni viaja al renderer.
  - Se guarda en `etc/github.token` cifrado con `safeStorage`. Para clonar con token se usa `GIT_ASKPASS` o `http.extraHeader` por variable de entorno, nunca en la URL.
- **Recetas:**
  - Solo se ejecutan con la casilla "Confío en este repositorio" marcada en ese proyecto. Se guarda `confiado: true` en el sitio.
  - Cada paso es reintentable. Ningún paso borra datos del usuario salvo los existentes y confirmados (restaurar con sobrescribir).
- **Fuentes de descarga:** Node desde nodejs.org (verificado con SHASUMS256) y Python desde el NuGet oficial (`api.nuget.org`, paquete `python`, verificado con hash). Se agregan a `HOSTS_PERMITIDOS`.
- **Procesos y puertos:**
  - Los procesos de proyecto solo escuchan donde su comando indique. Se buscan puertos libres para `uvicorn` y `vite` con la lista de reservados.
  - El MCP escucha en `127.0.0.1:<puerto configurable, 7790 por defecto>` con un token Bearer aleatorio. Las acciones destructivas piden confirmación en la ventana.
- **Métricas:**
  - Se muestrean cada 3 s solo si la ventana está visible.
  - En Windows se lee CPU y RAM por PID con un solo `Get-CimInstance Win32_PerfFormattedData_PerfProc_Process` (o `Get-Process`) por muestra, nunca uno por servicio.
- **Commits:** pequeños, en español, con formato `tipo: …` y la línea `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Cada agente agrega solo sus archivos.

## Review Focus

1. **Repositorio privado con token:** el token no aparece en `.git/config`, en `git remote -v`, ni en logs o eventos, y el clon funciona. Prueba en la Task 5.
2. **`.env.example` ausente o con variables raras:** la receta crea un `.env` mínimo válido y nunca sobrescribe un `.env` existente sin confirmación. Prueba en la Task 4.
3. **"Traer cambios" con cambios locales sin guardar o ramas divergentes:** no se toca nada y se avisa en claro. Prueba en la Task 5.
4. **Proceso de proyecto que muere en bucle** (por ejemplo `npm run dev` sin dependencias): el reinicio con espera creciente termina en "error" con el final del log, sin consumir CPU. Prueba en la Task 6.
5. **Cambio de idioma o de tema en caliente:** la interfaz no se rompe y no quedan textos sin traducir. Prueba en la Task 15.

- `type PasoReceta = {id: string; tipo: TipoPaso; titulo: string; args?: Record<string, unknown>; opcional?: boolean}`
- `TipoPaso = 'composer-install'|'env-crear'|'key-generate'|'bd-crear'|'bd-restaurar'|'migrar'|'storage-link'|'npm-ci'|'npm-build'|'python-venv'|'pip-install'|'pgvector-activar'|'sitio-crear'|'comando'`
- `recetaPorDefecto(det: Deteccion): PasoReceta[]`, según la spec 3.1:
  - **Laravel:** composer-install, env-crear, key-generate, bd-crear, migrar, storage-link, npm-ci, npm-build y sitio-crear (con https).
  - **CI3:** composer-install (si existe), env-crear, bd-crear, bd-restaurar (opcional, pide archivo) y sitio-crear.
  - **CI4:** igual que CI3, más un paso migrar con `php spark migrate`.

- `class EjecutorRecetas`:

  - `estado(sitioId): EstadoReceta`

  - Exige `sitio.confiado === true`; si no, falla con 'Marque "Confío en este repositorio" para ejecutar la receta'.
  - Solo puede haber una receta por proyecto a la vez.
- El estado se persiste en `run/receta-<id>.json` para mostrarlo tras reiniciar.

- [ ] Pruebas con pasos falsos: orden, detención en error, reintentar y omitir, exigencia de `confiado`, concurrencia y persistencia.

### Task 4: Pasos de receta

**Files:**
- Create: `packages/core/src/proyectos/pasos/{composer,env,laravel,bd,node,python,sitio,comando}.ts`
- Test: `packages/core/test/pasos.test.ts`

**Interfaces y reglas por paso** (todos usan el `Ejecutor`/`Lanzador` con streaming de líneas, `windowsHide`, cwd = carpeta del proyecto y el PATH de runtimes del proyecto):

- **`composer-install`:** `php -c <ini> composer.phar install --no-interaction --prefer-dist`, con el PHP del sitio.
- **`env-crear`:**
  1. Si `.env` existe, no lo toca y marca el paso como `listo` con la línea "Ya existe .env; no se modificó". La opción `args.sobrescribir` exige confirmación de la UI y antes copia a `run/env-<id>.respaldo` (Review Focus 2).
  2. Si no existe, copia `.env.example` o, sin él, genera un mínimo según el tipo.
  3. Rellena `APP_URL` y `APP_NAME`, y el bloque de conexión de la BD con `bloqueEnvSitio`, respetando el lector del tipo.
  4. Mailpit se configura si está instalado.
  5. Escribe con `valorEnv` (comillas simples) y atómicamente.
- **`key-generate`:** `php artisan key:generate --force`, solo si `APP_KEY` está vacío.
- **`bd-crear`:** crea la base (y su usuario, si `args.usuario`) en el motor detectado; si ya existe, no hace nada.
- **`bd-restaurar`:**
  - `args.archivo` debe venir de un diálogo, igual que las rutas elegidas. Usa `Respaldos.restaurar`.
  - Si la base tiene tablas, exige `args.confirmarSobrescribir`; si falta, el paso termina en error pidiendo confirmación.
- **`migrar`:** `php artisan migrate --force` (`--seed` si `args.semilla`); en CI4, `php spark migrate`.
- **`storage-link`:** `php artisan storage:link`; si ya existe, el paso es `listo`.
- **`npm-ci`:** `npm ci`, o `npm install` si no hay lock.
- **`npm-build`:** `npm run build`, solo si existe el script `build`.
- **`python-venv`:** `python -m venv .venv`.
- **`pip-install`:** `.venv\Scripts\python -m pip install -r requirements.txt`, o `-e .` si hay `pyproject`.
- **`pgvector-activar`:** `ClientePostgres.activarVector(base)`; si pgvector no está instalado, error que invita a "Instalar pgvector".
- **`sitio-crear`:** `Nucleo.guardarSitio` con el tipo, el PHP, el dominio y HTTPS. Si hay procesos (uvicorn o vite), los registra en `sitio.procesos` con un puerto libre.
- **`comando`:** `args.comando: string[]` sin shell.

- [ ] Pruebas con `Ejecutor` falso: argumentos exactos de cada paso, reglas de `.env` (no sobrescribir, respaldo, `.env` mínimo), CI3 con su lector, FastAPI con puerto libre.

### Task 5: Git y GitHub

**Files:**

- Modify: catálogo (si se decide instalar git portable) y `plataforma/tipos.ts`

**Interfaces:**
- `class Git`:
  - `disponible(): Promise<{git: string|null; gh: string|null; ghSesion: boolean; usuario?: string}>`: busca `git` y `gh` en el PATH y en las rutas conocidas (`C:\Program Files\Git\cmd`, `C:\Program Files\GitHub CLI`). La sesión de `gh` se mira con `gh auth status`.
  - `clonar(url, destino, {token?}): Promise<void>`:
    - Valida la URL (`https://` o `git@`) y que el destino no exista o esté vacío.
    - Con token usa `git -c credential.helper= -c http.extraHeader="Authorization: Basic <base64(x-access-token:token)>"` pasado por la variable `GIT_CONFIG_COUNT/KEY/VALUE`, de modo que el token no queda en la línea de comandos ni en `.git/config` (Review Focus 1).
    - Con `gh` usa `gh repo clone owner/name destino`.
    - Emite el progreso.
  - `estado(carpeta): Promise<{rama, cambiosLocales: number, adelante: number, atras: number, remoto: string|null}>`
  - `traerCambios(carpeta): Promise<{actualizado: boolean; cambios: {composerLock, packageLock, migraciones: string[], requirements}}>`: hace `git fetch` y `git pull --ff-only`. Si hay cambios locales o divergencia, lanza 'Hay cambios sin guardar…' o 'La rama divergió…' sin tocar nada (Review Focus 3). Compara `HEAD@{1}..HEAD` para saber qué cambió.
- `class GitHub`:
  - `repos({buscar?, pagina?}): Promise<{nombre, completo, privado, descripcion, actualizado, url}[]>`: con `gh repo list --json …` si hay sesión; si no, con la API REST y el token (`fetch` con `Authorization`, paginado).
  - `instalarGh()`: `winget install --id GitHub.cli -e`.
  - `iniciarSesionGh()`: abre `gh auth login --web` en una terminal visible, porque requiere interacción.
- **Token:** lo guarda main (`apps/desktop/src/main/secretos.ts`, Task 11) y se pasa como argumento a `clonar`/`repos`. El núcleo nunca lo guarda.

- [ ] Pruebas con un `Ejecutor` falso:
  - Argumentos y variables de entorno del clon con token: no está en args ni en la URL.
  - El clon con `gh`.
  - El parseo de `gh repo list`.
  - `traerCambios` con cambios locales, divergencia y avance rápido.
  - La detección de qué cambió.
- [ ] Prueba real con un repositorio público pequeño en una carpeta temporal (con red).
- [ ] Commit `feat(core): git y GitHub con token fuera de la URL y traer cambios seguro`.
