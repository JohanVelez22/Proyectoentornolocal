# WolfCore Dev — Etapa A: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** sobre el MVP, renombrar a WolfCore Dev y sumar HTTPS local, bases de datos (MySQL, MariaDB, PostgreSQL+pgvector, Redis, MongoDB) con crear/respaldar/restaurar/importar y Adminer, Composer y terminal por sitio, Mailpit, IA local con Ollama y servidor FTP.

**Architecture:** todo vive en `packages/core` detrás de `Nucleo` (TS puro, Vitest). Cada servicio nuevo es una `DefServicio` declarativa que reutiliza el `Supervisor`, el `Instalador` y el estado real ya existentes. `apps/desktop` solo agrega rutas IPC en la lista blanca y pantallas Vue.

**Tech Stack:** el del MVP (Node ≥22.12, TS estricto, Vitest, zod, Electron 45, Vue 3, Naive UI, Pinia), más `node-forge` (CA y certificados), `ftp-srv` (servidor FTP), `basic-ftp` (solo pruebas), `mysql2` y `pg` (consultas de administración) y `yauzl` (ya presente).

**Spec:** `docs/superpowers/specs/2026-11-18-etapa-a-design.md`. El spec del MVP, `docs/superpowers/specs/2026-11-17-proyectoentornolocal-design.md`, sigue vigente para todo lo que este plan no cambie.

## Global Constraints

- Nombre visible **WolfCore Dev**. `appId` es `com.johanvelez.wolfcoredev`. La carpeta de datos es `%LOCALAPPDATA%\WolfCoreDev`. Los marcadores de hosts son `# >>> WolfCore Dev (no editar a mano)` / `# <<< WolfCore Dev`. El repositorio y los paquetes npm conservan su nombre.
- Todo texto visible va en español y en `apps/desktop/src/renderer/i18n/es.ts`. Todo error se explica en lenguaje claro y sin trazas.
- `@pel/core` no importa `electron`. Lo que depende del sistema operativo va detrás de `Plataforma` o de un `Ejecutor` inyectable.
- Los binarios salen solo de fuentes oficiales con SHA-256 verificado:
  - MySQL: dev.mysql.com / cdn.mysql.com
  - MariaDB: archive.mariadb.org
  - PostgreSQL: get.enterprisedb.com
  - MongoDB: fastdl.mongodb.org y downloads.mongodb.com
  - Redis: github.com/redis-windows/redis-windows
  - Mailpit: github.com/axllent/mailpit
  - Ollama: github.com/ollama/ollama
  - Composer: getcomposer.org
  - Adminer: github.com/vrana/adminer
  - pgvector (código fuente): github.com/pgvector/pgvector

  Los hosts nuevos se agregan a `HOSTS_PERMITIDOS`. Las URL de GitHub pueden redirigir a su CDN de descargas; se verifica la huella.
- Versiones: el último parche de MySQL 8.4 LTS, MariaDB 11.4 LTS, PostgreSQL 17, Redis 8, MongoDB 8 (y su mongosh), Mailpit y Ollama estables. Se calculan las huellas al implementar, con red. Si una línea no tiene versión para Windows, se usa la anterior y se anota en el reporte.
- Puertos por defecto y alternativos para cuando FlyEnv ocupa el estándar:

  | Servicio | Por defecto | Alternativo |
  |---|---|---|
  | MySQL | 3306 | 3308 |
  | MariaDB | 3307 | 3309 |
  | PostgreSQL | 5432 | 5433 |
  | Redis | 6379 | 6380 |
  | MongoDB | 27017 | 27018 |
  | Mailpit SMTP | 1025 | — |
  | Mailpit web | 8025 | — |
  | Ollama | 11434 | — |
  | FTP | 2121 | — |
  | Pasivos FTP | 50000–50100 | — |
  | Adminer | 8090 | — |
  | HTTPS | 443 | — |

  Todos escuchan en 127.0.0.1, salvo el FTP si el usuario activa "red local".
- Datos en `data/<servicio>/<mayor.menor>/`. Desinstalar nunca borra datos. "Borrar datos" pide escribir el nombre del servicio.
- Las restauraciones e importaciones van a una base nueva o vacía. Si la base destino tiene tablas, se exige `confirmarSobrescribir: true`. Importar nunca escribe en el servidor de origen.
- Las claves nunca van en una URL (Adminer recibe servidor y usuario, no la clave) ni en archivos del proyecto.
- La CA se instala en el almacén **de usuario** (`certutil -user -addstore Root`). Las pruebas nunca la instalan en el almacén real.
- Cada acción nueva es un método de `Nucleo`, de modo que el MCP de la Etapa B solo tenga que publicarla.
- Commits pequeños en español con `tipo: descripción` y la línea `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No se copia código de FlyEnv ni de ServBay.

## Review Focus

1. **Respaldo `.rar` real de Diamantes (pg_dump custom con extensión `.sql` dentro):** `tar.exe` lo extrae, o falla con el mensaje "Descomprima el archivo y elija el .sql o .dump que contiene". Nunca restaura a medias en una base con datos. Prueba en la Task 8.
2. **Puerto ocupado por FlyEnv (3306/5432/443):**
   - el servicio no arranca;
   - el aviso dice proceso y PID y ofrece el puerto alternativo;
   - los vhosts HTTP siguen sirviendo aunque haya sitios HTTPS pendientes.

   Pruebas en las Tasks 3 y 10.
3. **Restaurar en una base con tablas sin `confirmarSobrescribir`:** se rechaza con "La base X ya tiene tablas" y no se ejecuta nada. Prueba en la Task 8.
4. **Túnel abierto en un sitio con `redirigirHttps`:** el túnel responde 200, sin bucle de redirección. Prueba de plantilla en la Task 10.
5. **FTP con `..`, rutas absolutas o letras de unidad:** el usuario de un sitio no sale de su carpeta. Prueba en la Task 12.

### Task 9: Instalador de pgvector

**Files:**
- Create: `packages/core/src/bd/pgvector.ts`
- Test: `packages/core/test/pgvector.test.ts`

**Interfaces:**
- Produces: `class InstaladorPgvector` (emite `'instalacion:progreso'` con `servicio:'pgvector'`).
  - `estado(): Promise<{buildTools: boolean; instalado: boolean; version: string|null}>`. Las Build Tools se buscan con `vswhere.exe -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath`; `instalado` se determina por `vector.control` en `share/extension` del PostgreSQL activo.
  - `instalarBuildTools(): Promise<{ok:boolean; motivo?}>`: `winget install --id Microsoft.VisualStudio.2022.BuildTools -e --accept-package-agreements --accept-source-agreements --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"`. Si `winget` no existe, `{ok:false, motivo:'winget-ausente'}`.
  - `compilarEInstalar()`:
    1. descarga el zip del código de `pgvector-src` (catálogo) y lo extrae;
    2. ejecuta `cmd /c "call <vcvars64.bat> && set PGROOT=<pg> && nmake /F Makefile.win && nmake /F Makefile.win install"` con cwd en el código;
